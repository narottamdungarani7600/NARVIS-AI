# Contributing to NARVIS

Thank you for your interest in contributing to NARVIS.

## How to Contribute

1. Fork the repository and create a feature branch.
2. Follow the project's architecture and coding standards.
3. Keep changes focused and well documented.
4. Add or update tests where appropriate.
5. Submit a pull request with a clear description of the change.

## Development Guidelines

- Follow the standards described in PROJECT_DEVELOPMENT_GUIDE.md.
- Use Python best practices and type hints.
- Keep modules independent and reusable.
- Write clear docstrings for public interfaces.
- Avoid introducing unrelated changes.

## Code Style

- Use Python 3.10+ syntax.
- Follow PEP 8 conventions.
- Use 4-space indentation.
- Keep line lengths readable.

## Pull Request Expectations

- Provide a concise summary of the change.
- Explain why the change is needed.
- Mention any relevant tests or validation steps.
